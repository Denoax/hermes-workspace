# Hermes workspace

Read and apply $reference-led-design for visual continuation. Reuse the actual owned Paseo/Kona composition and inspected official sources in SOURCE_RECORD.md. No generated media, fake telemetry or subjective approval claims.

The user UI runs without elevation on IPv4 loopback 127.0.0.1:18791. Its dedicated Brave profile receives an HttpOnly, SameSite=Strict cookie over a private CDP pipe. Host, Origin, CSRF, method schemas, body/depth/rate/output limits are enforced on the server. Credentials never enter URLs, localStorage or exported logs. No remote provider, tunnel or listener is added.

`install_desktop.py` installs the normal-user launcher, entry and UI service and replaces only the Steam preference string. Steam remains installed. Opening/focusing Hermes starts no VM, model or inference window. Homebrew opens the existing normal Hermes TUI separately, only when its original alias, 65536 context and four configuration hashes are verified.

The catalog at `~/HermesLab` holds explicit projects, inert editable copies, immutable exports and durable sessions/jobs. Folder import requires native selection, a reviewed file list and an expiring hash-bound ticket. Hidden/known credential metadata, links, special/binary/oversize files and mount escapes are excluded or rejected. This filename policy cannot certify that ordinary source text contains no secret; review an import before committing it. Original repositories stay unchanged until the user applies a hash-bound reviewed diff. Apply is limited to one existing independently validated file whose admitted base still equals the imported original; no host build or execution accompanies it.

Chat advertises only scoped read tools. The declared Python contract is `program.py`: JSON integer array in, clamp each value to 0..100 out. The C++ contract is `solution.cpp`: whitespace integers in, squares out. These are owned acceptance contracts, not a general proof of arbitrary project correctness. Prototype tools run only in worker_a, as guest UID 1000; generated code/compiler execution runs as separate guest UID 1001. A newly booted worker_b performs independent validation. Each job uses at most 16 files / 32 KiB, 12 tool actions, 8 agent iterations, 1024 tokens per request and an absolute 480-second job deadline. Additional wire/output/context limits can reject larger conversations. No shell, cloud fallback, arbitrary compiler command or dependency download is inherited.

The root broker owns the durable job ledger, FIFO queue, pidfd owner identity, lease, committed arm and cleanup. One model/job executes at a time. UI and opt-in `hermes-worker lab` share it. Replays, unknown models/settings/root paths/operations fail closed. UI Stop revokes outside work; a terminal outcome follows workload cleanup. Model/backend byte pins are verified before acceptance and remain tied to root-owned immutable file identities; polling checks drift without repeating large hashes.

Native setup is one frozen transaction. `workspace_setup.py apply` updates only this lab, retains source/config/media recovery and registers runtime files, thin directories/symlinks, dynamic backend hooks, UI/adapter entries and exactly the created lab accounts. `workspace_acceptance.py qualify` runs current-source watchdogs, offline compilers, pinned guest tool-wire fixtures and actual disposable systemd removal/reinstall before inference. The scripted protocol backend is explicitly not model evidence.

After qualification, `workspace_acceptance.py run` is an explicit new 30-minute choice that pauses normal Qwen and automatically restores its original service, alias, context and hashes. It does not renew the deadline. Do not repeat it under an expired or closed approval. Live failures remain recorded. The original 2/3 + 2/3 smoke and withheld matrix are preserved; tool-assisted B08 is a separate experiment.

`workspace_recovery.py plan` and `remove` perform exact registered recovery with drift checks, normal recovery and hook retirement before referenced code. Copied/original weights, base images, package recovery, evidence, catalog/browser data, source backups and fixed setup/recovery helpers remain retained. Production removal is distinct from the disposable test and is not silently applied.
