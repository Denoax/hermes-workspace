# Hermes UI overhaul

Read and apply `$reference-led-design` for visual continuation. Use the bundled policy when unavailable. Preserve current work, inspect published references and original documentation, use licensed real assets and original code, and verify actual rendered output and motion. Do not generate visual media or treat test results as human approval.

The existing stdlib authenticated loopback service serves `workspace/ui/` directly. There is no frontend build framework, dependency installer or parallel preview app. Start with the existing Hermes desktop pin, or `systemctl --user start hermes-workspace.service` followed by `~/.local/bin/hermes-workspace`. The authenticated route is http://127.0.0.1:18791/hermes-workspace. Opening the URL in an unrelated browser does not transfer authentication.

The frontend uses DM Sans for readable controls/messages and Bebas Neue for short headings. Dark is the initial theme; Appearance persists light/dark and a system/reduced-motion preference in the owner-only catalog. The numbered project rail, matte surfaces, restrained focus and static empty-view rings adapt Mani's portfolio and the supplied authored reference. A project/conversation dialog replaces the rail below 820 px. Files reserves space on wide screens and uses a modal drawer at 1200 px and below. Native dialog focus, explicit Tab cycling, Escape and focus return are retained through immediate dismissal and short CSS transitions.

Existing projects, three-column sessions, messages, jobs, imports, originals and review tables are preserved. Three additive presentation tables hold optional conversation titles, current view/editor state and per-session composer drafts. Unnamed conversations use the first user's message, shortened deterministically, or New conversation. Rename never edits a transcript. Session model identity remains immutable: changing model creates a new conversation and preserves the selected tool mode. No credentials or transcripts move into browser storage.

Editor drafts up to 32 KiB and composer drafts up to 48 KiB are stored privately. The existing request body and snapshot limits still apply. A larger editor draft stays in the current page and must be saved before reconnect; switching away from an unsaved editor asks before discarding it. This is a measured storage boundary, not a general file editor guarantee. Reopening a changed file requires explicit discard of the old draft. Save/import/apply retain their original guarded contracts.

Start lab displays the existing prepared native command; it never starts or renews a window. Stop uses the existing selected-job cancellation operation. Send requires connection, a selected project/conversation, installed guest tool profile, a real open window and a bounded snapshot. A server 429 denial before dispatch receives one delayed retry; network failures and ambiguous mutations are not retried. File and model output stay literal DOM text, with fenced code and a restricted link renderer. Tool events are disclosures. No fake stream or percentage is generated.

`Details` contains read-time live readiness and separately labelled historical smoke evidence. Historical Normal 2/3 and Abliterated 2/3, failed B08, and the withheld matrix stay unchanged. Homebrew retains its existing normal-profile native terminal route.

Validation: `python3 -B scripts/validate.py --integration`, `python3 -B -m unittest tests.test_ui_overhaul -v`, and native Node `--check workspace/ui/app.js`. `workspace/probe_overhaul.py` uses authenticated native Brave to capture current UI and labelled renderer fixtures. `workspace/probe_quality.py CHECKPOINT/before/workspace/ui` samples baseline/candidate browser CPU work and checks computed contrast and editor hash refusal. These probes must use owned review data; they do not certify actual model/VM execution or human motion quality. Run them only with awareness that selection/draft preferences change in the owner catalog.
