# V5 acceptance

Read and apply `$reference-led-design`. All numbers below that specify thresholds
are proposed Hermes regression criteria, not measured properties of a reference.
Use the individual ledger tasks and v4-to-v5 row map; no count-only completion.

## Source and real application

Bind evidence to the relevant source files, compiled asset hashes and actual
service/launcher identity. Distinguish the archive baseline, prepared candidate,
merged checkout, installed runtime and published commit. Confirm the existing
profile/catalog and actual pin on port 18791. No reset or global cleanup.

Before final delivery, close temporary acceptance servers/workers and relaunch
the real pin after a fresh idle boundary. Send a new normal turn, switch to the
candidate and send a new turn, then recover normal and send again. Both models
must retain history/reload and contextual follow-ups. Check growing real output,
real compute cancellation, one-run/one-message retry and no duplicate sends.
Preserve an existing draft plus attachment through failure and reconnect. Record
load/readiness/first-public-output/total separately without calling observer
reconnect times model latency. The candidate's linked artifact stays hash-pinned;
model listing loads no weights. Final normal context/configuration pins match.

## Visual inspection

Use actual desktop scaling/DPR/zoom, plus 1280×800, 1440×900, 1920×1080 and
390×844, both themes. Inspect populated folders, branches, colors, long titles,
selected/hover/focus states, messages, code blocks, attachments, errors and
approvals. Also test 200% zoom and narrow width without hidden essential actions.
Do not save private user content in public captures; use positively identified
temporary test records or sanitization, never delete unknown records.

Empty composer target is at most 96 CSS px at desktop widths and 112 CSS px at
390px, including its toolbar and excluding external readiness/attachment cards.
If available width needs a different limit, record the measured conflict and
solution; do not hide permissions or clip Send. Input grows with content to the
existing bounded maximum. Model identity is readable; full readiness is
accessible. Real microphone control remains available through the plus menu where
the narrow toolbar omits its shortcut.

Files/Details/Settings trigger rectangles move at most 1 CSS pixel on menu open.
Opening or switching panels must not move the shell, composer or reading anchor.
Test visible coordinates at actual desktop scaling and at zoom, corners and
center of targets, keyboard Tab/Shift-Tab, Enter/Space, Escape, outside click and
focus return. No invisible overlay can receive clicks for another control.

For every R01–R11, save matched state/size/theme comparisons and concrete
geometry/material/typography/input/semantic/motion differences. Keep original
creator/source/rights records. A related Pinterest pin is not a proved canonical
identity. R01 has two actual detents. R08 remains pending for live guest states if
qualification is blocked. Fixtures may guide development and must be labelled.

## Motion, performance and accessibility

Review uninterrupted normal-speed production sequences and rapid reversals,
open/close/reopen and cancellation, not only extracted still frames. Include
reasoning, reflections, lifecycle status, search preview, folder flap, voice
play/pause, task completion and Delete confirm/cancel. Preserve the repaired
DeleteButton mount width. Test buddy distant positions, reversal, press, drag
cancel, sleep/wake, keyboard theme change, hidden/offscreen and cleanup.

Measure actual frame/input work during both local-model workloads and at idle on
the user's hardware. State capture duration, refresh/scaling, workload and adverse
samples. Video encoding rate is not display cadence; rAF timing is not direct GPU
presentation timing. Avoid continuous full-screen shader work or a performance
claim based only on an empty app. Reduced motion, reduced transparency and forced
colors have useful states. Verify focus, readable contrast and semantic labels;
physical assistive-technology review is separate if unavailable.

## Permissions, guest and devices

Confirm mode/custom policy persists across same-conversation model switch/reload;
direct API and final dispatch cannot bypass it. Attach named current test results
for expiry, version drift, consumed-once replay, wrong conversation, concurrent
execution, file descriptor/symlink boundaries, stale base/read drift, original
mode preservation, finite tool budgets, no self-approval, late result rejection,
minimal audit and revocation. Host-original application requires separate
one-use scoped approval. Keep actual guest revoke/cancel separate from fixtures.

All-five VM watchdog qualification must bind current policy hashes and boot ID.
Then prove supported guest task/confinement/tool result, expiry/cancel/revoke and
normal recovery. Preserve failed boot traces and no-host-fallback enforcement.

Voice playback uses actual media time and waveform; recording uses real samples,
stop/cancel limits and released tracks. Test consent denial, late permission,
device loss and no upload before explicit send. Physical listening, intelligible
speech and actual unplug review stay pending unless observed. Do not remotely
record ambient audio to fill an acceptance row. Reboot is a separately coordinated
review, not an unattended loop action.

## Completion

Keep functional, source, visual, native, physical and human results distinct.
The loop validates omission/hash/scope metadata, not truth or quality. Human
approval cannot be self-issued. A fully prepared engineering review can be
delivered with clearly named BLOCKED/manual rows; label the release PARTIAL in
that case. `validate --complete` must fail until all required rows really pass.
