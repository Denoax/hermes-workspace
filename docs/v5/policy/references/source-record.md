# Source-to-implementation record

Use the project's existing design log or reference register. Add one short record per new visual component; update or reuse settled records. Do not require this for each spacing adjustment.

| Field | Record |
| --- | --- |
| Source | Original URL and creator; supporting original/official documentation when a technique needs it. |
| Inspected detail | Specific composition, material, motion or interaction observed; include timestamp/state when useful. Separate observations from inferred implementation. |
| Adaptation | What principle the new code applies, and how content, typography, geometry, colour and behaviour fit this project. |
| Provenance and reuse | Credible origin/process/code evidence; any reused asset/code and applicable permissions/credits. Exclude known generated media and sources whose origin remains insufficiently established. Do not infer a reuse licence from publication. |
| Output evidence | Actual implementation file(s), browser capture/recording and relevant interaction checks; explicitly retain unverified items. |

Inspect linked sources rather than filling this table from remembered appearances or search snippets. Do not fabricate a creator, process statement, test result or approval. Prefer a small coherent set of references over a large catalogue of effects.
