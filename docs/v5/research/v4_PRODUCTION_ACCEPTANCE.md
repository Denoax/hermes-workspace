Do not replace production checks with isolated test servers. Record exact checkout, installed Python/native artifacts, built UI manifest, service identity, model hashes/aliases/context, authenticated route and run timestamps. Do not publish private keys, cookie values, authorization headers, home file contents or full process environments.

1. Reproduce and repair the reported failure.
   Capture the user's real 18791 admission failure before changing it. Establish the actual failed socket condition and lifecycle cause. After the fix, verify the frozen installation metadata and protected socket/peer checks remain intact. Confirm admission through the actual authenticated app context.

2. Real pin, real catalog, both models.
   Launch the existing Hermes pin, create a clearly identified test conversation, select only verified local models and obtain at least three connected user/assistant turns from each model through that actual UI. Reload history and verify the correct model/session continuity. Measure admission wait, cold load, first token, total reply and error behavior. Use a fact from an earlier turn in a later reply to exercise history. Do not relabel a fixture or direct backend request as a pin test.

3. Streaming, retry and cancellation.
   Observe real streamed output and cancel real compute. Retry a genuinely failed turn without duplicate queued generations/messages. Check double-click/reconnect handling, preserved attachments/draft, service restart messaging and clear loading/recovery state for the slow candidate.

4. Final cleanup regression.
   Stop isolated test backends, remove only clearly identified test-only state and restore healthy normal Qwen at context 65,536 with the original configuration hashes. Close acceptance workers. Fresh-launch from the actual pin and send a new real message through 18791. Then switch to the candidate through the UI and obtain a real reply using the normal supported model window. Restore normal Qwen afterward and prove another production send works. This sequence addresses the gap exposed by the latest screenshot.

5. Cold launch, idle and socket lifecycle.
   Within the already qualified native procedure, verify socket activation and normal-model recovery do not remove production admission. Close and reopen the app, cross the configured idle transition, and repeat a send. After a permitted service/socket restart, show recovery via the app. Do not delete a live control socket by hand, alter watchdog clocks or unlock the desktop for automation. Reboot only within an explicitly safe native recovery plan; otherwise mark it unverified.

6. Permissions.
   Use the real mode selector and granular controls. A denied tool request must fail at the server and final dispatcher, including a direct API attempt. Exercise allow-once, narrow session grants, denial, revocation, replay, expiry, wrong conversation and path/symlink escape. Show successful permitted read, workspace edit/diff and qualified guest execution with actual results. The model cannot approve its own action. Plain chat works in Chat only without execution grants.

7. Visual parity and actual interactions.
   Complete every R01–R11 entry in PARITY_LOCK, with continuous motion where applicable and the actual production pin output. Verify full rail, selected colors, compact composer, stable Files/Details/Settings popovers, plus menu, real source-backed statuses and pointer-follow buddy. Confirm keyboard focus, touch fallback, forced colors, system/app reduced motion and visibility cleanup.

8. Real microphone and playback.
   Test browser grant/denial, app permission toggle, record/stop/cancel, device loss, track release, playback and upload/transcription as supported. A prerecorded fixture only proves the fixture path. Physical microphone/listening and subjective motion stay unverified if the user is unavailable; do not fabricate approval.

Do not repeat the old delete-all request: preserve new user conversations and projects. Back up reversible migrations and restrict cleanup to positively identified new test records. Retain sanitized failure evidence.

Meaningful regression checks should cover changed contracts and user-visible failure paths. Existing test totals are historical, not evidence for new permission enforcement or production readiness. Report each requirement PASS, FAIL, BLOCKED or PARTIAL with concrete evidence and scope. Do not make a single “all done” claim with a failing live chat requirement.
